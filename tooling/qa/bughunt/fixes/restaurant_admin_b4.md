## Follow-ups for other packets

- packages/ui (owner: ui/storefront packet): `DialogContent` has no max-height, so any dialog taller than the screen clips (root cause of RESPONSIVE_B2-02). Suggest a default `max-h-[calc(100dvh-2rem)] overflow-y-auto` (or a DialogBody/sticky footer pattern like restaurant/_components/scroll-dialog.tsx). Also: a consumer `max-w-md/lg` class replaces the base `max-w-[calc(100%-2rem)]` via tailwind-merge, so dialogs go edge to edge on phones; using `sm:max-w-*` in consumers (as done here) or a base `max-sm:` cap avoids it. And Radix controlled dialogs without a DialogTrigger lose focus to <body> on close (RESPONSIVE_B2-11) — a DialogContent-level "return focus to the element focused at open" (see OpenerCapture in scroll-dialog.tsx; it must read activeElement during render because child `autoFocus` runs before onOpenAutoFocus) would fix every admin dialog at once.
- admin-core (apps/admin/src/components/ui/kpi-card.tsx): at 390 the 2-column KPI grids truncate Thai labels ('ออเดอร์ทั้ง…', 'ยอดขาย (…' on /restaurant/orders?tab=history). Not in this packet's two categories; noted only.
