## Checked and holding (no change needed)

- Closed handler never cancels a paid / processing / fulfilled order (status guard + current-payment guard); a superseded payment (renewed, or money on another payment) is a no-op.
- Paid handler: already-applied payment → no-op; another payment for a paid order → refundRequired "ชำระซ้ำ"; closed order → target check flags; short payment → flag (RV-09 copy). Wallet purchase fulfils inside the order transaction; stock out on the last code → wallet credited back + payment refunded (two concurrent buyers: SKIP LOCKED gives the code to one, the other is refunded).
- Double refund / retry after refund: adminMarkRefunded and adminRetryOrder both take the order row lock; refunded / refundedAt → `already` / `refunded`; wallet refund is idempotent (topup_refund:<id>).
- Two concurrent stock imports: per-tenant advisory lock + unique (tenant_id, code_hash). Migration 0010 applied (drizzle id 11; code_hash column, unique index, FK confdeltype 'r'; 0 rows without hash).
- tenant_id present on every new query (services orders / wallet / refund-flag, admin orders, commerce wallet_topup refs, integrations loaders).
