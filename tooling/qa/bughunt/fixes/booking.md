## Follow-ups addressed to this packet (done)
- payments-api 3.2 closed handlers for "booking" and "patient_package": registered in packages/modules/booking/src/register.ts (onBookingPaymentClosed, onPatientPackagePaymentClosed – pending purchase → status "cancelled").
- payments-api 3.1 paid handlers: onBookingPaid / onPatientPackagePaid return refundRequired(...) instead of silently applying (cancelled / no-show / duplicate / cancelled purchase).
- cancel / reschedule void the open deposit with cancelPayment(…, { runHandler: false }) (see COR-08 / COR-09); recordCashDeposit voids the open QR first; createPackagePayment (renew) voids the stale package QR.
- Services form slug input: keeps a trailing "-" while typing and trims on blur / submit / name-derived (typingSlug / finalizeSlug contract of apps/admin/src/lib/slug.ts). Local copies in services/service-form.tsx because the booking slug schema allows Thai / Unicode letters, which @/lib/slug would strip.
- Service / staff / clinic image uploads (shared uploadBookingImageAction in apps/admin/.../services/actions.ts): sniffImage() decides the type (no SVG / HTML), stored with the sniffed ext + MIME, folder whitelisted; the old "point LOCAL_UPLOAD_DIR at web" env hack removed (core storage writes to the storefront uploads dir since AC-01).

## Design decisions
- Slip under review on cancel: a `pending_verification` deposit is NOT voided when the booking is cancelled (only `pending` / `failed` are). It may represent money already transferred; leaving it lets the admin verify it — approve → payment paid + refund flag (target check "booking cancelled"), reject → failed. Voiding it would leave no refund trail. The expiry sweep never touches it either.
- Capacity × staff model: see the comment block above `isGroupService()` in packages/modules/booking/src/services/availability.ts. Staffed + capacity>1 = one staff per guest; classes / rooms = requiresStaff off.
- Lock order for writers that touch payments: payments (FOR UPDATE) → booking (FOR UPDATE), the same order markPaid → onBookingPaid uses. Booking creation additionally takes the per-tenant advisory lock first.
- Course sessions are spent when the online booking is made (not at the visit) so two bookings cannot use the last session; cancel returns it, no-show forfeits it.
