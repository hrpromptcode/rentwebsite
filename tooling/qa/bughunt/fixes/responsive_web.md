## Notes for a successor

- **New shared hooks/tokens (packages/ui/src/styles/globals.css):** `[data-reveal-mask]` / `[data-reveal-thai]` (TextReveal word masks), `--header-h` (HeaderShell measures it; SSR estimates keyed on `data-site-header` / `data-sticky`), `--bottom-ui` now lives on `:root`, `html { scroll-padding-top/bottom }`, Tailwind colour `text-primary-ink` (primary mixed 22% towards foreground — use it for any ≤14px brand-coloured text instead of `text-primary`). Sticky panels should use `top-[calc(var(--header-h,0px)+1rem)]`, never a hard-coded top-24/28.
- **Calendar markup changed (B2-10):** day buttons are `button[role=gridcell][data-date=YYYY-MM-DD]` with Thai aria-labels; unbookable days are `aria-disabled="true"` (still focusable) instead of `disabled`. QA scripts were updated accordingly (`[aria-label="<iso>"]` → `[data-date="<iso>"]`, `:not([disabled])` → `:not([aria-disabled])`): tooling/qa/booking-journey.ts, tooling/qa/bughunt/admin_b2-newbook.ts, storefront_booking_restaurant-book2/-book3/-fab.ts. The admin new-booking dialog uses the same MonthCalendar.
- **Environment during this run:** `/api/booking/days` answered 500 for salon and clinic (service/db code being edited concurrently by another packet — packages/modules/booking/src/services/*, packages/db migrations 0005/0006 untracked; nothing in this packet touches them). So every day currently renders as "เต็ม"; the live runs of RESPONSIVE_B2-10-verify.ts print SKIP for the "choose a day" step and the script's third run stubs the availability API (Playwright route) to cover it. Rerun once the API is back.
- **Follow-ups (not done here):** (0) product-card titles / descriptions with `line-clamp-2` (commerce product card h3, clinic service card p) still clip 1.4–2.3px of the top Thai marks on their first line (below the analyzer's 2.5px threshold; needs a tiny padding-top inside the clamp box). (1) Thai display headings rendered without TextReveal (hero `Heading` fallback when reveal is off, other `.heading-display` uses) still use line-height 0.95–1, so stacked marks can touch the line above; consider `.heading-display:lang(th)` leading ≥ 1.2 (needs a design pass because `text-5xl` etc. set line-height in the utilities layer). (2) The platform landing (apps/web/src/app/(platform)/page.tsx) `<main>` has no `overflow-x-clip`; it has no left-reveal blocks today. (3) SectionHeading eyebrows inside `tone="primary"` sections would be primary-on-primary (no current template does this).
