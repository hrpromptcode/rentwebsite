# 02 — ประเภทเว็บไซต์ทั้งหมดและระบบโมดูล

> ตอบคำถาม: จะ "cover ทุกประเภท" ได้อย่างไรโดยไม่ต้องเขียนเว็บใหม่ทุกครั้ง, แต่ละประเภทต้องมีอะไรบ้าง, 5 ประเภทหลักที่คุณระบุ (เติมเกม, ขายของ, จองคิว, คลินิก, ร้านอาหาร) ต้องทำอะไรเป็นพิเศษ

## 1. โครงสร้าง 3 ชั้น

```
ชั้น 1  Core modules      ทุกเว็บมี: CMS/Pages, Media, Theme, Customers, Payments, Notifications, SEO, Analytics, Forms, Blog, Staff, Promotions
ชั้น 2  Vertical modules  เปิดตามประเภท: Commerce, Booking, Top-up+Wallet, Restaurant, Clinic, Rental, LMS, Membership, Events, Listings, Donation
ชั้น 3  Templates         สูตรสำเร็จ 30+ แบบ = โมดูล + ธีม + หน้า + ข้อมูลตัวอย่าง + เช็กลิสต์
```

## 2. Core modules (ทุก tenant ได้ใช้)

| โมดูล | ความสามารถ (MVP) | เพิ่มภายหลัง |
|---|---|---|

| **Theme & Brand** | โลโก้/favicon/OG, สี, ฟอนต์ไทย, มุมโค้ง, เลย์เอาต์, preset, โหมดมืด | Custom CSS (แพ็กเกจสูง), ตลาดธีม |

| **Analytics** | ผู้เข้าชม, หน้ายอดนิยม, แหล่งที่มา, conversion (สั่งซื้อ/จอง) แบบ privacy-friendly; เชื่อม GA4/Meta Pixel/TikTok Pixel ของร้าน | รายงานขั้นสูง, cohort |

| **Blog / News** | บทความ, หมวด, แท็ก, ปกบทความ, SEO | ผู้เขียนหลายคน, กำหนดเวลา |
| **Staff & Roles** | เชิญพนักงาน, role/permission, 2FA, audit log | หลายสาขา (locations) |
| **Promotions** | คูปอง (เปอร์เซ็นต์/บาท/ส่งฟรี), โปรตามยอด, จำกัดจำนวน/เวลา, โค้ดเฉพาะลูกค้า | Flash sale, bundle, แต้มสะสม |

## 3. Vertical modules

### 3.1 Commerce (ร้านค้าออนไลน์) — โมดูลที่ใช้ซ้ำมากที่สุด

- **สินค้า**: หมวดหมู่หลายระดับ, สินค้า + ตัวเลือก (สี/ไซซ์ → variants), SKU, บาร์โค้ด, รูปหลายรูป, รายละเอียด rich text, สินค้าดิจิทัล (ไฟล์/โค้ด), สินค้าพรีออเดอร์, สินค้าบริการ (ไม่ตัดสต็อก)
- **สต็อก**: ต่อ variant (และต่อสาขาภายหลัง), แจ้งเตือนใกล้หมด, จองสต็อกเมื่อสั่ง (หมดอายุถ้าไม่ชำระ), ประวัติการเคลื่อนไหว
- **ตะกร้า/ชำระเงิน**: guest checkout, คูปอง, ค่าส่งตามน้ำหนัก/ยอด/โซน/ฟรีเมื่อถึงยอด, รับที่ร้าน, เก็บเงินปลายทาง, PromptPay/บัตร/โอน+สลิป
- **ออเดอร์**: สถานะ (รอชำระ → ชำระแล้ว → กำลังจัดส่ง → ส่งแล้ว → สำเร็จ / ยกเลิก / คืนเงิน), พิมพ์ใบปะหน้า, หมายเหตุ, ประวัติ, ส่งข้อความหาลูกค้า
- **ขนส่ง**: กรอกเลขพัสดุเอง (MVP) → เชื่อม API Flash/Kerry/J&T/ไปรษณีย์ หรือ aggregator (Shippop) เพื่อเรียกรับพัสดุและพิมพ์ label
- **รีวิว**: ให้ดาว+รูปหลังได้รับสินค้า, ร้านอนุมัติ
- **บัญชีลูกค้า**: ประวัติ, ติดตามพัสดุ, ที่อยู่, wishlist
- **รายงาน**: ยอดขาย, สินค้าขายดี, ลูกค้าประจำ, ส่งออก Excel
- Storefront pages: `/products`, `/products/[slug]`, `/collections/[slug]`, `/cart`, `/checkout`, `/orders/[id]`, `/account/*`
- Sections: product-grid, featured-product, collection-list, countdown-sale
- Thai-specific: ใบเสร็จ/ใบกำกับภาษีอย่างย่อ, ที่อยู่แบบ จังหวัด/อำเภอ/ตำบล/รหัสไปรษณีย์ (dataset ไทย), ขนาดกล่อง/น้ำหนักสำหรับขนส่งไทย, เก็บเงินปลายทาง

### 3.2 Booking (จองคิว/นัดหมาย) — ฐานของ คลินิก, สปา, ซาลอน, ฟิตเนส, ติวเตอร์, ช่าง, สัตวแพทย์, สนามกีฬา

- **บริการ**: ชื่อ, ระยะเวลา, ราคา, buffer ก่อน/หลัง, ต้องมัดจำไหม, ทำพร้อมกันได้กี่คน (class/คอร์ท), หมวด
- **ผู้ให้บริการ (staff/resource)**: หมอ/ช่าง/เทรนเนอร์/ห้อง/คอร์ท, บริการที่ทำได้, ตารางทำงานรายสัปดาห์, วันหยุด/ลา, สาขา
- **Slot engine**: คำนวณช่วงว่างจาก (ตารางทำงาน − วันหยุด − การจองเดิม − buffer) ÷ ขั้นเวลา (15/30/60 นาที), จองล่วงหน้าได้สูงสุด N วัน, ขั้นต่ำก่อนถึงเวลา, timezone
- **การจอง**: เลือกบริการ → เลือกผู้ให้บริการ (หรือใครก็ได้) → เลือกวัน/เวลา → ข้อมูลลูกค้า (เบอร์+OTP หรือ LINE) → มัดจำ/ชำระ → ยืนยัน; จองหลายบริการต่อเนื่อง, จองซ้ำ (recurring)
- **นโยบาย**: ยกเลิก/เลื่อนได้ก่อน X ชม., ค่าปรับ/ริบมัดจำ, no-show tracking, รายชื่อรอ (waitlist)
- **แจ้งเตือน**: ยืนยันทันที, เตือน 24 ชม./1 ชม. (LINE/SMS), แจ้งร้านเมื่อมีจอง/ยกเลิก
- **ปฏิทินหลังบ้าน**: มุมมองวัน/สัปดาห์/ต่อพนักงาน, ลากเลื่อน, บล็อกเวลา, walk-in, เช็กอิน, สถานะ (จอง/ยืนยัน/มาแล้ว/เสร็จ/ไม่มา)
- **Sync**: Google Calendar สองทาง (ภายหลัง), iCal feed
- Storefront: `/book`, `/book/[service]`, `/services`, `/staff/[slug]`, `/account/bookings`
- Sections: booking-widget (ฝังในหน้าใดก็ได้), service-list, staff-grid

### 3.3 Top-up & Wallet (เว็บเติมเกม / สินค้าดิจิทัล)

- **แคตตาล็อกเกม**: เกม (โลโก้, แบนเนอร์, ฟิลด์ที่ต้องกรอก เช่น UID/Server/Zone), แพ็กเกจ (เพชร 100 = 35 บาท), ราคาสมาชิก/ตัวแทน (tier), สถานะพร้อมขาย/หมด, เวลาเติมโดยประมาณ
- **รูปแบบการเติม 3 แบบ** (ร้านเลือกต่อแพ็กเกจ):
  1. **Supplier API อัตโนมัติ**: ส่งคำสั่งไปผู้ขายส่ง (ร้านใส่ API key ของตัวเอง), poll/webhook สถานะ, รองรับหลาย supplier + fallback
  2. **สต็อกโค้ด**: ร้านอัปโหลดโค้ด/บัตร (CSV), ระบบจ่ายอัตโนมัติ 1 โค้ดต่อออเดอร์ (lock แบบ atomic กันซ้ำ), แจ้งเตือนเมื่อเหลือน้อย
  3. **เติมมือ**: ออเดอร์เข้าคิว, พนักงานเติมแล้วกดยืนยัน + แนบหลักฐาน, SLA timer
- **Wallet ของลูกค้าในร้าน**: เติมเงินเข้า wallet (PromptPay/สลิป/TrueMoney voucher), ตัดจาก wallet เมื่อซื้อ, คืนเข้า wallet เมื่อเติมล้มเหลว, ประวัติรายการ, ledger แบบ double-entry (ห้ามแก้ยอดตรง ๆ), ยอดติดลบไม่ได้
- **ตัวแทน/ระดับสมาชิก**: ราคาตาม tier, อัปเกรด tier เมื่อยอดสะสมถึง, โค้ดแนะนำ
- **Anti-fraud**: จำกัดรายการ/นาที/IP/อุปกรณ์, ตรวจสลิปซ้ำ (hash + เลขอ้างอิงธนาคาร), blacklist UID/เบอร์, ยืนยัน OTP ก่อนซื้อครั้งแรก, บล็อกประเทศ, log ทุกการเปลี่ยนสถานะ
- **ประวัติ/ตรวจสอบ**: ลูกค้าเช็กสถานะด้วยเลขออเดอร์, หน้าร้านแสดง feed "เติมล่าสุด" (ปิดบังข้อมูล), สถิติเกมยอดนิยม
- **หลังบ้าน**: dashboard ยอดเติม/กำไรต่อแพ็กเกจ (ราคาทุนจาก supplier), คิวเติมมือ, จัดการสต็อก, ตั้งราคาจำนวนมาก, สถานะ supplier (ยอดเงินคงเหลือใน supplier)
- Storefront: `/`, `/games/[slug]`, `/topup/status/[id]`, `/wallet`, `/account`
- ธีมตั้งต้น: Dark gaming (neon), Light clean
- ข้อควรระวัง: wallet ที่เติมล่วงหน้าแล้วใช้ได้ "เฉพาะในร้านนั้น" โดยทั่วไปไม่เข้าข่าย e-money แต่ถ้าใช้ข้ามร้าน/ถอนเป็นเงินสดได้จะเข้าข่ายกำกับโดย ธปท. → ออกแบบให้ wallet อยู่ต่อ tenant เท่านั้น และไม่ให้ถอนออก (คืนเงินผ่านช่องทางเดิมเท่านั้น); ร้านเติมเกมต้องจดทะเบียนพาณิชย์อิเล็กทรอนิกส์

### 3.4 Restaurant (ร้านอาหาร/คาเฟ่)

- **เมนู**: หมวด, เมนู, รูป, ราคา, ตัวเลือก/ท็อปปิ้ง (modifiers: ระดับเผ็ด, ไข่ดาว +10), แพ้อาหาร/มังสวิรัติ, เมนูหมดชั่วคราว, เวลาขาย (เมนูเช้า), หลายภาษา
- **QR สั่งอาหารที่โต๊ะ**: สร้าง QR ต่อโต๊ะ (พิมพ์ได้), ลูกค้าสแกน → สั่ง → ส่งเข้าครัว, เพิ่มออเดอร์ในรอบเดิม, เรียกพนักงาน, ขอบิล, จ่ายที่โต๊ะ (PromptPay) หรือจ่ายที่เคาน์เตอร์, ปิดโต๊ะ
- **สั่งกลับบ้าน/เดลิเวอรี่**: เลือกเวลารับ, รัศมีจัดส่ง/ค่าส่ง, ชำระล่วงหน้า, ลูกค้าติดตามสถานะ (รับออเดอร์ → กำลังทำ → พร้อม → ส่งแล้ว)
- **ครัว (KDS)**: หน้าจอครัวแบบเรียลไทม์, ติ๊กเสร็จต่อรายการ, แยกสถานีครัว/บาร์ (ภายหลัง), พิมพ์ใบครัว (ESC/POS ผ่าน print agent ภายหลัง)
- **จองโต๊ะ**: จำนวนคน, เวลา, โซน, มัดจำ, เตือน, no-show, จัดการแผนผังโต๊ะแบบง่าย
- **โปรโมชัน**: ส่วนลดเมนู, ชุดอาหาร, Happy hour
- **รายงาน**: ยอดขายต่อเมนู/ช่วงเวลา/โต๊ะ, เวลาทำอาหารเฉลี่ย
- Storefront: `/menu`, `/t/[tableCode]` (สแกน QR), `/order`, `/reserve`
- Sections: menu-highlight, hours-location, reservation-cta
- หมายเหตุ: ไม่ตั้งใจแทน POS เต็มรูปแบบ (Wongnai POS, Ocha) ในปีแรก — เน้นเว็บ+QR+จอง และเชื่อม POS ภายหลัง

### 3.5 Clinic & Patient (คลินิกความงาม/ทันตกรรม/กายภาพ/แพทย์ทั่วไป)

- ต่อยอดจาก **Booking** (หมอ = staff, หัตถการ = service, ห้อง = resource)
- **ทะเบียนผู้ป่วย**: HN อัตโนมัติ, ข้อมูลส่วนตัว, แพ้ยา, โรคประจำตัว, ผู้ติดต่อฉุกเฉิน, รูป, เอกสาร (บัตร ปชช. — เก็บเข้ารหัส), consent รักษา/ถ่ายรูป/การตลาด (PDPA มาตรา 26: ข้อมูลสุขภาพเป็นข้อมูลอ่อนไหว ต้องมี explicit consent)
- **การมาตรวจ (visit)**: นัด → เช็กอิน → ซักประวัติ → บันทึกการรักษา (SOAP note, รูปก่อน/หลัง, แบบฟอร์มเฉพาะทาง) → สั่งยา/สินค้า → คิดเงิน → นัดครั้งถัดไป
- **คอร์ส/แพ็กเกจ**: ซื้อคอร์ส 10 ครั้ง, ตัดครั้งเมื่อใช้, หมดอายุ, โอนสิทธิ์, รายงานคอร์สค้างใช้ (หนี้สินของคลินิก)
- **การเงิน**: ใบเสร็จ/ใบกำกับภาษี, ค่ามือหมอ (commission) รายงาน
- **ความปลอดภัยเพิ่มเติม**: เข้ารหัสฟิลด์ (treatment notes, เลขบัตร), access log ว่าใครเปิดเวชระเบียนใคร, role ละเอียด (ฟรอนต์เห็นแค่นัด, หมอเห็นเวชระเบียน), ส่งออก/ลบตามคำขอผู้ป่วย
- Storefront: หน้าคลินิก, บริการ/ราคา, ทีมแพทย์, รีวิว, จองออนไลน์, `/account` ดูนัด/คอร์สคงเหลือ
- กฎหมายที่เกี่ยว: การโฆษณาสถานพยาบาลต้องได้รับอนุญาต (ร้านรับผิดชอบเนื้อหา แต่ควรมีคำเตือนในระบบ), ข้อมูลสุขภาพ = ต้องแยก bucket + เข้ารหัส + DPA กับคลินิก

### 3.6 Rental (ที่พัก/เช่ารถ/เช่าอุปกรณ์) — การจองแบบ "ช่วงวัน"

- หน่วยให้เช่า (ห้อง/รถ/กล้อง), จำนวนหน่วยต่อประเภท, ราคาต่อคืน/วัน + ราคาตามฤดูกาล/วันหยุด, ขั้นต่ำกี่คืน, เช็กอิน/เอาต์, มัดจำ/ประกัน, ส่วนเสริม (อาหารเช้า, คาร์ซีท)
- ค้นหาตามวันที่ → ว่าง → จอง → ชำระ; ปฏิทินความพร้อมหลังบ้าน, บล็อกวัน, iCal sync กับ Airbnb/Booking.com (ภายหลัง)
- ใช้กับ: โรงแรม/รีสอร์ต/โฮสเทล, บ้านพัก, เช่ารถ/มอเตอร์ไซค์, เช่าชุด/อุปกรณ์, ห้องประชุม/co-working (รายชั่วโมงใช้ Booking แทน)

### 3.7 LMS / Course (คอร์สออนไลน์/โรงเรียนสอนพิเศษ)

- คอร์ส → บท → บทเรียน (วิดีโอฝังจาก YouTube/Vimeo/Bunny Stream, ไฟล์, ควิซ), ราคา/ฟรี, ตัวอย่างฟรี, drip content, ใบรับรองเมื่อจบ, ความคืบหน้า, ถาม-ตอบใต้บทเรียน
- ชั้นเรียนสด = Booking (class แบบหลายคน)
- ป้องกันการแชร์: watermark ชื่อผู้เรียนบนวิดีโอ, จำกัดอุปกรณ์

### 3.8 Membership / Subscription content

- แพ็กเกจสมาชิกรายเดือน/ปี, เนื้อหาเฉพาะสมาชิก (บทความ/วิดีโอ/ไฟล์), ส่วนลดสมาชิก, บัตรสมาชิกดิจิทัล (QR), ต่ออายุอัตโนมัติ (บัตร) หรือแจ้งเตือนโอน; ใช้กับฟิตเนส, แฟนคลับ, สมาคม, ครีเอเตอร์

### 3.9 Events / Tickets

- อีเวนต์, รอบ, ประเภทบัตร (ราคา/จำนวน/ช่วงขาย), ที่นั่งแบบโซน, คูปอง, e-ticket QR, แอปเช็กอิน (PWA), รายชื่อผู้เข้าร่วม, คืนบัตร; ใช้กับ งานสัมมนา, คอนเสิร์ตเล็ก, เวิร์กช็อป, วิ่ง

### 3.10 Listings (อสังหาฯ, รถมือสอง, ไดเรกทอรี)

- ประกาศ + แอตทริบิวต์ตามประเภท (ห้องนอน/ตร.ม./ราคา/ทำเล — ปี/ไมล์/เกียร์), แกลเลอรี, แผนที่, ฟิลเตอร์, เปรียบเทียบ, ฟอร์มสอบถาม/นัดชม (→ Booking), สถานะขายแล้ว, นำเข้า CSV

### 3.11 Donation / Non-profit

- แคมเปญ, เป้าหมาย, บริจาคครั้งเดียว/รายเดือน, ใบอนุโมทนา/ใบเสร็จ e-Donation (เชื่อมกรมสรรพากรภายหลัง), รายชื่อผู้บริจาค (เลือกเปิดเผย)

### 3.12 Multi-vendor marketplace — **ภายหลัง (ซับซ้อนสูง)**

- หลายผู้ขายใต้ tenant เดียว, แยกออเดอร์ต่อผู้ขาย, ค่าคอมมิชชัน, payout → ต้องการระบบการเงินแบบ marketplace ซึ่งเกี่ยวกับใบอนุญาต; ไม่อยู่ในปีแรก

## 5. เจาะลึก 5 ประเภทหลักที่คุณระบุ — flow และจุดที่ต้องระวัง

### 5.1 เว็บเติมเกม

```
ลูกค้า: เลือกเกม → กรอก UID/Server → เลือกแพ็กเกจ → (login/OTP ครั้งแรก) → เลือกจ่าย (wallet / PromptPay / สลิป)
       → ชำระ → สถานะ "กำลังเติม" → เติมสำเร็จ (แจ้ง LINE/หน้าเว็บ) / ล้มเหลว (คืนเข้า wallet อัตโนมัติ)
ระบบ:  สร้าง topup_order (pending) → ชำระสำเร็จ (paid) → event topup.paid → worker เลือกวิธี:
       supplier API → เรียก → รอ callback/poll (processing) → fulfilled/failed
       code stock   → SELECT ... FOR UPDATE SKIP LOCKED 1 โค้ด → ส่งให้ลูกค้า → fulfilled
       manual       → เข้าคิวหลังบ้าน → พนักงานยืนยัน → fulfilled
ร้าน:   dashboard: ยอด/กำไร, คิวเติมมือ, สต็อก, สถานะ supplier, รายงาน fraud
```

จุดระวัง: ราคาทุนเปลี่ยนบ่อย (ให้ตั้งราคาเป็น % margin จากทุนได้), supplier ล่ม (fallback + แจ้งลูกค้า), สลิปปลอม/ซ้ำ (ตรวจกับ API + hash), chargeback ถ้ารับบัตร (แนะนำ PromptPay/wallet เป็นหลัก), ห้ามให้ถอน wallet เป็นเงินสด, บันทึก ledger ทุกบาท

### 5.2 ร้านค้าออนไลน์

```
ลูกค้า: ดูสินค้า → เลือก variant → ตะกร้า → checkout (ที่อยู่ไทย 4 ระดับ, ขนส่ง, คูปอง) → ชำระ → ติดตามพัสดุ → รีวิว
ร้าน:   เพิ่มสินค้า (เร็ว: ชื่อ ราคา รูป 1 นาที) → รับออเดอร์ (แจ้ง LINE) → ตรวจสลิป (อัตโนมัติ) → แพ็ก → ใส่เลขพัสดุ/เรียกขนส่ง → เสร็จ
```

จุดระวัง: ตัดสต็อกตอนไหน (จองตอนสั่ง 30 นาที ถ้ารับสลิป; ตัดตอนชำระถ้าบัตร), ค่าส่งไทยซับซ้อน (ตามน้ำหนัก + พื้นที่ห่างไกล), เก็บเงินปลายทางต้องมีสถานะ "รอเก็บเงิน", ร้านส่วนใหญ่ขายใน LINE/Facebook ด้วย → ต้องมีลิงก์สินค้าแชร์ง่าย และ "สร้างออเดอร์แทนลูกค้า" จากหลังบ้าน

### 5.3 จองคิว

```
ลูกค้า: เลือกบริการ → เลือกคน/ใครก็ได้ → ปฏิทินแสดงเฉพาะวันที่ว่าง → เลือกเวลา → เบอร์ + OTP (หรือ LINE) → มัดจำ (ถ้ามี) → ยืนยัน → ได้รับเตือนก่อนนัด → เลื่อน/ยกเลิกเองได้ตามนโยบาย
ร้าน:   ตั้งบริการ/พนักงาน/ตารางทำงานครั้งเดียว → ดูปฏิทินรายวัน → เช็กอิน → ปิดงาน → ลูกค้าได้ลิงก์รีวิว
```

จุดระวัง: slot engine ต้องเร็ว (คำนวณล่วงหน้าเป็นช่วง ๆ และ cache), double-booking (unique constraint `(staff_id, start)` + transaction), timezone, เวลาพักเที่ยง, จองติดกันต้องเคารพ buffer, no-show สูงในไทย → มัดจำผ่าน PromptPay ช่วยได้มาก, เตือนผ่าน LINE ดีกว่า SMS (ถูกกว่าและอ่านมากกว่า)

### 5.4 คลินิก

```
ผู้ป่วยใหม่: จองออนไลน์ → กรอกประวัติล่วงหน้า + ให้ consent (PDPA) → มาถึง เช็กอิน → พบแพทย์ (บันทึก) → ชำระ/ตัดคอร์ส → นัดถัดไป
ผู้ป่วยเก่า: login ด้วยเบอร์ → เห็นคอร์สคงเหลือ/นัด → จองซ้ำ 2 คลิก
คลินิก:     ฟรอนต์เห็นคิว, หมอเห็นเวชระเบียนเฉพาะคนไข้ของตน, เจ้าของเห็นรายงาน
```

จุดระวัง: ข้อมูลสุขภาพ = sensitive → เข้ารหัสฟิลด์, access log, DPA, ห้ามใช้ทำการตลาดโดยไม่มี consent แยก; การโฆษณาสถานพยาบาล (ก่อน-หลัง, ราคาโปร) มีข้อกำหนดของกรมสนับสนุนบริการสุขภาพ — ใส่คำเตือนในหลังบ้าน; คอร์สคงเหลือคือ "หนี้" ต้องรายงานชัด; ใบรับรองแพทย์/ใบเสร็จต้องมีเลขที่รันต่อเนื่อง

### 5.5 ร้านอาหาร

```
ที่ร้าน:   สแกน QR โต๊ะ 5 → เมนู (ไทย/อังกฤษ) → สั่ง + ท็อปปิ้ง → ครัวได้รับ (เสียง) → ทำ → เสิร์ฟ → สั่งเพิ่ม → ขอบิล → จ่าย PromptPay ที่โต๊ะ/เคาน์เตอร์ → ปิดโต๊ะ
กลับบ้าน: เมนู → เลือกเวลารับ/ส่ง → ชำระล่วงหน้า → ร้านรับออเดอร์ → แจ้ง "พร้อมรับ" ทาง LINE
จองโต๊ะ:  วัน/เวลา/จำนวน → มัดจำ (เลือกได้) → เตือน → เช็กอิน
```

จุดระวัง: เรียลไทม์ครัว (Supabase Realtime/SSE), เมนูหมดต้องสะท้อนทันที, โต๊ะหนึ่งมีหลายคนสั่งจากมือถือหลายเครื่อง (session ต่อโต๊ะ + ชื่อผู้สั่ง), อินเทอร์เน็ตร้านไม่เสถียร (หน้าครัวต้อง reconnect เอง), ร้านส่วนใหญ่มี POS แล้ว → ตำแหน่งของเราคือ "เว็บ + สั่งผ่าน QR + จอง" ไม่ใช่แทน POS
