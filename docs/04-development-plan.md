# 04 — แผนการพัฒนา ฟีเจอร์ เฟส ทีม แนวปฏิบัติ และข้อกฎหมาย

> ตอบคำถาม: ต้องสร้างหน้าจออะไรบ้างสำหรับใคร, ทำอะไรก่อนหลัง, ใช้เวลาเท่าไรกับทีมขนาดไหน, ทำงานอย่างไรให้ไม่พัง, ต้องทำอะไรให้ถูกกฎหมายไทย

## 1. ขอบเขต MVP (สิ่งที่ "เปิดรับเงินลูกค้ารายแรก" ต้องมี)

| ต้องมี (MVP) | ยังไม่ต้องมี |
|---|---|
| สมัคร → สร้างเว็บจากเทมเพลตใน 5 นาที | ตลาดธีม, ธีมพรีเมียม |
| ธีม: โลโก้ สี ฟอนต์ preset + page builder 10 sections | Custom CSS, A/B test |
| Commerce ครบวงจร (สินค้า ตะกร้า ชำระ ออเดอร์) | ขนส่ง API อัตโนมัติ (กรอกเลขพัสดุเองก่อน) |
| รับเงิน: PromptPay (gateway) + โอน/สลิป + ตรวจสลิปอัตโนมัติ | บัตรเครดิตผ่านทุกเจ้า, ผ่อนชำระ |
| แจ้งเตือน: อีเมล + LINE OA ของร้าน | SMS broadcast, web push |
| บัญชีลูกค้าด้วย OTP/LINE | Loyalty, segment |
| subdomain ฟรี + custom domain (คุณเพิ่มให้ด้วยมือได้ก่อน) | โดเมนอัตโนมัติเต็มรูปแบบ (เฟส 2), ขายโดเมน |
| Billing: trial 14 วัน → แพ็กเกจ → ระงับเมื่อค้าง | Proration ซับซ้อน, คูปองแพลตฟอร์ม |
| Superadmin: รายการร้าน, impersonate, ระงับ, เปลี่ยนแพ็กเกจ | Dashboard การเงินละเอียด |
| 5 เทมเพลต: ร้านค้า, สินค้าดิจิทัล, บริษัท, landing, ร้านอาหาร (เมนู) | เทมเพลตอื่น (ตามเฟส) |
| PDPA พื้นฐาน: privacy generator, consent, export, ลบ | DSAR workflow อัตโนมัติ |

## 2. ฟีเจอร์แยกตามแอป

### 2.1 หน้าร้าน (apps/web)

- หน้า core: Home (sections), หน้าอิสระ, บล็อก, ติดต่อ/แผนที่, นโยบาย, ค้นหา, 404/503 ตามธีม, หน้า "ปิดปรับปรุง/ค้างชำระ"
- Route ของโมดูลที่เปิด (สินค้า/จอง/เติม/เมนู/ห้อง/คอร์ส …)
- บัญชีลูกค้า: เข้าสู่ระบบ OTP/LINE/อีเมล, โปรไฟล์, ที่อยู่, ประวัติ (ออเดอร์/จอง/wallet), ออกจากระบบ, ลบบัญชี
- ตะกร้า/ชำระเงิน (Commerce), วิดเจ็ตจอง (Booking), สถานะเติม (Top-up), สั่งที่โต๊ะ (Restaurant)
- SEO: sitemap/robots ต่อ tenant, canonical ไปโดเมนหลัก, OG, structured data, หน้าโหลดเร็ว
- สลับภาษา TH/EN, cookie consent, ปุ่มแชต LINE/โทร, แบนเนอร์ประกาศของร้าน
- Preview mode สำหรับหลังบ้าน (เห็น draft)

| ตั้งค่า | ข้อมูลร้าน/สาขา/เวลาทำการ, ภาษา/สกุลเงิน/เขตเวลา, การชำระเงิน (เชื่อม gateway, PromptPay ID, บัญชีธนาคาร, ตรวจสลิป), ขนส่ง/ค่าส่ง, แจ้งเตือน (เชื่อม LINE OA, เทมเพลตข้อความ), โดเมน, พนักงานและสิทธิ์, นโยบาย/กฎหมาย (generator), การเรียกเก็บเงิน (แพ็กเกจ, ใบแจ้งหนี้, วิธีจ่าย), API/webhooks, ส่งออกข้อมูลทั้งหมด, ปิด/ลบร้าน |

ออกแบบให้ใช้บน **มือถือ** ได้จริง (เจ้าของร้าน SME ส่วนใหญ่จัดการจากมือถือ): ตรวจสลิป, เปลี่ยนสถานะ, ตอบลูกค้า, เพิ่มสินค้าด้วยกล้อง

### 2.3 คอนโซลของคุณ (console.rentweb.app)

- Tenants: ค้นหา/filter (แพ็กเกจ, สถานะ, ประเภท, วันสมัคร), รายละเอียด, impersonate (บันทึก log + แบนเนอร์), เปลี่ยนแพ็กเกจ/โควต้าเฉพาะราย, ขยาย trial, ระงับ/คืน/ลบ, โน้ตภายใน
- Billing: MRR/ARR, churn, trial → paid, ใบแจ้งหนี้ค้าง, คืนเงิน, คูปอง, รายงานภาษี (VAT)
- Catalog: เทมเพลต, ธีม, โมดูล (เปิด/ปิดระดับแพลตฟอร์ม), ประกาศ/แบนเนอร์, คู่มือ
- โดเมน: คิวตรวจ DNS, ปัญหา SSL, hostname ทั้งหมด
- การใช้งานและต้นทุน: storage/bandwidth/jobs ต่อร้าน, ร้านที่ใช้หนักผิดปกติ, ต้นทุนต่อร้าน
- ระบบ: feature flags ต่อร้าน, สุขภาพคิว/webhook/integration, error rate (ลิงก์ Sentry), งาน cron ล่าสุด
- Support: inbox ticket, ส่งอีเมล/LINE หาเจ้าของร้าน, เทมเพลตคำตอบ
- Abuse/Compliance: รายงานเว็บผิดกฎ, keyword flags (การพนัน, สินค้าต้องห้าม), KYC-lite สำหรับหมวดเสี่ยง (เติมเกม)
- Audit log ของทีมคุณ

### 2.4 เว็บการตลาดและ Onboarding

1. **หน้าแพลตฟอร์ม**: เลือกตามประเภทธุรกิจ → ดูเดโมสด (tenant ตัวอย่างต่อเทมเพลต) → ราคา → FAQ → สมัคร
2. **สมัคร**: อีเมล/Google/LINE → ยืนยัน
3. **Wizard 3 ขั้น** (≤ 2 นาที): ประเภทธุรกิจ → ชื่อร้าน + slug (เช็กว่างทันที) + ข้อมูลติดต่อ → เลือก preset ธีม (preview สดด้วยชื่อร้านจริง) → "สร้างเว็บ"
4. **Provisioning** (< 5 วินาที, ทำใน job เดียว): insert `tenants`, `tenant_domains` (subdomain), `tenant_modules` ตามเทมเพลต, seed หน้าเว็บ/สินค้าตัวอย่าง, สร้าง owner membership, อุ่น cache, ส่งอีเมลต้อนรับ
5. **เช็กลิสต์ในหลังบ้าน**: อัปโลโก้ → ปรับสี → ลบตัวอย่าง/เพิ่มของจริง 1 รายการ → ตั้งช่องทางรับเงิน → เชื่อม LINE → ตั้งโดเมน (ถ้ามี) → เผยแพร่ · แสดง % ความคืบหน้า และ "ตัวอย่างลูกค้าเห็นอะไร"
6. **Trial 14 วัน** ไม่ต้องใส่บัตร → เตือนวันที่ 7, 12, 14 (อีเมล + แบนเนอร์) → เลือกแพ็กเกจ → จ่าย (บัตร: อัตโนมัติ / PromptPay: ต่อเดือนหรือรายปี) → active · trial หมด → `suspended` (หน้าร้านปิด, หลังบ้านเข้าได้เฉพาะหน้าชำระเงิน) → 30 วันไม่จ่าย → ลบพร้อมอีเมลแจ้ง 3 ครั้ง

### 2.5 วงจรการเรียกเก็บเงิน (Billing lifecycle)

- แพ็กเกจรายเดือน/รายปี (รายปีลด ~2 เดือน), อัปเกรดมีผลทันที (คิดส่วนต่างตามสัดส่วน), ดาวน์เกรดมีผลรอบถัดไป
- ใบแจ้งหนี้/ใบเสร็จ PDF อัตโนมัติ (ชื่อ/เลขผู้เสียภาษีของร้าน), ใบกำกับภาษีเมื่อคุณจด VAT, รองรับลูกค้านิติบุคคลที่หัก ณ ที่จ่าย 3% (แนบหนังสือรับรองหัก ณ ที่จ่าย)
- สถานะ: `trialing → active → past_due (วัน 1–9, เตือน 1/3/7) → suspended (วัน 10) → cancelled → deleted (+30 วัน)`
- ยกเลิก: มีผลสิ้นรอบ, ส่งออกข้อมูลได้ถึงวันลบ, แบบสอบถามเหตุผล (วัด churn)
- โควต้า: ตรวจตอนสร้าง (สินค้า/ผู้ใช้/หน้า) และตอน cron (storage/ข้อความ) → เตือนที่ 80%, บล็อกการเพิ่มที่ 100% (ไม่ปิดหน้าร้าน)

## 3. เฟสการพัฒนา

หน่วย "pw" = person-week (1 คนทำ 1 สัปดาห์เต็ม)

### เฟส 0 — Foundation (6–8 pw)

สร้าง: monorepo + CI, schema core + RLS + `withTenant`, isolation test suite, middleware resolve tenant, Better Auth (staff/superadmin, 2FA), สร้าง tenant (API + wizard), theme engine + 2 presets, page builder core + 8 sections, media upload R2 + CDN, admin shell (nav, layout, table, form), console shell, billing data model + Stripe test mode, Sentry/PostHog, Dockerfile, docs/ADR
**เกณฑ์ผ่าน**: สร้าง 2 ร้านบน staging, แก้โลโก้/สี/หน้า Home แยกกัน, isolation test เขียว, preview deploy ต่อ PR ทำงาน

### เฟส 1 — Commerce + CMS + เปิด Beta (10–12 pw)

สร้าง: สินค้า/variants/สต็อก/หมวด, ตะกร้า/checkout (ที่อยู่ไทย, ค่าส่ง, คูปอง), Opn PromptPay + โอน/สลิป + ตรวจสลิป, จัดการออเดอร์, บัญชีลูกค้า OTP/LINE Login, แจ้งเตือนอีเมล + LINE OA, รีวิว, SEO, บล็อก, ฟอร์ม, legal generator, เทมเพลต 5 แบบแรก + demo tenants, billing จริง (Stripe + PromptPay), custom domain แบบคุณเพิ่มให้, help center เบื้องต้น
**เกณฑ์ผ่าน**: ร้านจริง 5–10 ร้าน (ฟรี 3 เดือนแลก feedback) ขายของได้จริง, ไม่มี incident ระดับข้อมูลรั่ว, LCP < 2.5 s

### เฟส 2 — Booking + Clinic + โดเมนอัตโนมัติ (8–10 pw)

สร้าง: slot engine + ทดสอบ, บริการ/พนักงาน/ตาราง/วันหยุด, flow จอง + มัดจำ + นโยบาย, ปฏิทินหลังบ้าน, เตือน LINE/SMS, waitlist, Clinic add-on (ผู้ป่วย, consent, visit, บันทึกเข้ารหัส, แพ็กเกจ/คอร์ส, access log), DNS checker + Vercel Domains API, เทมเพลต: จองคิว, คลินิก, ซาลอน/สปา, ฟิตเนส, สนาม/ห้อง, ติวเตอร์, สัตวแพทย์
**เกณฑ์ผ่าน**: จอง 1,000 ครั้งใน load test ไม่มี double booking, คลินิกนำร่อง 2 แห่งใช้จริง

### เฟส 3 — Top-up + Restaurant (10–12 pw)

สร้าง: wallet ledger + ทดสอบ, เกม/แพ็กเกจ/ราคา tier, supplier adapter + 1–2 adapter จริง, สต็อกโค้ด (atomic), คิวเติมมือ, กฎ anti-fraud, feed สถานะ; Restaurant: เมนู/modifiers, QR โต๊ะ + session, KDS realtime, pickup/delivery, จองโต๊ะ (reuse booking), รายงาน; เทมเพลต: เติมเกม, ไอเทม/บัตร, ร้านอาหาร QR, คาเฟ่สั่งล่วงหน้า
**เกณฑ์ผ่าน**: ledger สมดุลทุกกรณีทดสอบ (รวมคืนเงิน/ล้มเหลว/race), ร้านอาหารจริง 2 ร้านใช้ QR ตลอดวันโดยครัวไม่หลุด

### เฟส 4 — ขยาย (sprint 2–3 สัปดาห์ ต่อเนื่อง)

Rental/โรงแรม, LMS, Membership, Events, Listings, Donation; Public API + webhooks; หลายสาขา; ขนส่ง API (Shippop); broadcast marketing; Google Calendar sync; PWA ครัว/เช็กอิน; เนื้อหา EN; ตลาดธีม; รายงานขั้นสูง; ขายโดเมน; ย้ายข้อมูลจากระบบอื่น (นำเข้า Shopify/LnwShop CSV)

### เฟส 5 — Scale & Hardening (เมื่อ 300+ ร้าน)

Load test ทั้งระบบ, read replica, partitioning, ย้าย web/worker ไป container ถ้าค่า Vercel สูง, PITR, DR drill, pen test ภายนอก, เตรียม cell architecture, SLA สำหรับ Business/Enterprise

## 4. เวลาโดยรวมตามขนาดทีม (ถึงจบเฟส 3 = ครบ 5 ประเภทหลัก ≈ 34–42 pw)

| ทีม | เวลาจริงโดยประมาณ | หมายเหตุ |
|---|---|---|
| 1 คน (เต็มเวลา) | 9–11 เดือน | รวมเวลาตอบลูกค้า beta และงานที่ไม่ใช่โค้ด; เสี่ยงหมดแรง → แนะนำตัด Top-up ไปเฟสหลัง หรือจ้างเสริมเฉพาะ UI |
| 2 คน (full-stack + front/UX) | 4.5–5.5 เดือน | จุดคุ้มที่สุด; แบ่ง core/backend กับ UI/เทมเพลต |
| 3–4 คน | 3–4 เดือน | เริ่มเสีย overhead ประสานงาน; ต้องมีคนนำสถาปัตยกรรมชัด |
| จ้างเอเจนซี่ทำ MVP (เฟส 0–1) แล้วทีมในต่อ | 2–3 เดือนถึง beta | ต้อง own โค้ดและ docs ตั้งแต่แรก มิฉะนั้นต่อยอดยาก |

ตัวเลขนี้คือ "ทำได้ใช้ได้จริง" ไม่ใช่ "สมบูรณ์แบบ" — เผื่อ +20–30% สำหรับ feedback จากลูกค้า beta

## 5. แนวปฏิบัติทางวิศวกรรม

- **Git**: trunk-based, branch สั้น, PR ทุกอย่าง (ถ้าทำคนเดียว ใช้ self-review checklist + AI review), Conventional Commits, preview deploy ต่อ PR
- **Definition of Done** ต่อฟีเจอร์: tests ผ่าน (unit + integration ที่เกี่ยว), i18n ครบ, responsive มือถือ, a11y พื้นฐาน, audit log ถ้าเป็น mutation สำคัญ, migration ย้อนกลับได้, เอกสาร/คู่มือผู้ใช้อัปเดต, feature flag ถ้าเสี่ยง
- **Migrations**: expand → deploy → contract; ห้าม breaking ใน release เดียว; รันใน CI กับ DB สำเนา staging ก่อน prod
- **Feature flags ต่อ tenant** เพื่อปล่อยทีละกลุ่ม (beta → Pro → ทุกคน)
- **Release**: รายสัปดาห์ (วันอังคาร, ไม่ใช่ศุกร์), changelog ให้ลูกค้าอ่านในหลังบ้าน, rollback = redeploy เวอร์ชันก่อน (DB compatible)
- **ADR**: ทุกการตัดสินใจสถาปัตยกรรมเขียน 1 หน้าใน `docs/adr/`
- **Runbooks**: เว็บล่ม, DB เต็ม, คิวค้าง, webhook gateway ล้มเหลว, ลูกค้าขอข้อมูล/ลบ, โดเมนลูกค้าหมดอายุ, สลิปปลอมระบาด
- **ความลับ**: ไม่มี `.env` prod บนเครื่อง dev; secrets ใน Vercel/Doppler; หมุน key ทุก 6 เดือน

## 7. การดำเนินงาน (Operations) และการซัพพอร์ต

- ช่องทาง: LINE OA ของแพลตฟอร์ม (ลูกค้าไทยคาดหวัง), ticket ในหลังบ้าน, help center (บทความ + วิดีโอสั้นต่อประเภทเว็บ), สถานะระบบ (status page)
- SLA เป้าหมาย: uptime 99.9% (≈ 43 นาที/เดือน), ตอบ ticket Starter 24 ชม. / Pro 8 ชม. / Business 2 ชม. ในเวลาทำการ
- Monitoring: uptime ทุกโดเมนหลัก + ตัวอย่าง tenant, error rate, p95 latency, คิวค้าง, webhook ล้มเหลว, DB CPU/connections/storage, ค่าใช้จ่ายรายวัน (alert เมื่อผิดปกติ)
- Backup: รายวันอัตโนมัติ + PITR (เมื่อมีลูกค้าจ่ายเงิน > 50 ราย) + dump รายสัปดาห์นอก vendor; **ทดสอบ restore ทุกไตรมาส**
- Incident: ประกาศใน status page ภายใน 15 นาที, post-mortem ภายใน 3 วัน (ไม่โทษคน)
- Abuse: นโยบายเนื้อหา (ห้าม: การพนัน, ยา/อาวุธ/บุหรี่ไฟฟ้า/เหล้าออนไลน์, ละเมิดลิขสิทธิ์, หลอกลวง), ตรวจ keyword อัตโนมัติตอนเผยแพร่, ปุ่มรายงาน, takedown ภายใน 24 ชม., KYC-lite (ทะเบียนพาณิชย์/บัตร ปชช.) สำหรับเติมเกม/สินค้าดิจิทัล
- Cost review รายเดือน: ต้นทุนต่อร้าน, ร้านที่ใช้ทรัพยากรผิดปกติ, การใช้ quota

## 8. กฎหมายไทยและการปฏิบัติตาม (ไม่ใช่คำแนะนำทางกฎหมาย — ให้ทนายตรวจก่อนเปิดบริการ)

### 8.1 PDPA (พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล 2562)

| บทบาท | ข้อมูล | หน้าที่ของคุณ |
|---|---|---|
| คุณ = **ผู้ควบคุมข้อมูล** | ข้อมูลเจ้าของร้าน/พนักงาน (บัญชี, บิล) | privacy notice ของแพลตฟอร์ม, ฐานทางกฎหมาย (สัญญา), ความปลอดภัย, สิทธิเจ้าของข้อมูล |
| คุณ = **ผู้ประมวลผลข้อมูล** | ข้อมูลลูกค้าของร้าน (ผู้ซื้อ/ผู้ป่วย) | ทำตามคำสั่งร้าน, **DPA (ข้อตกลงประมวลผล) อยู่ใน ToS**, บันทึกกิจกรรม, แจ้งร้านเมื่อข้อมูลรั่ว, ลบ/คืนเมื่อเลิกใช้ |
| ร้าน = ผู้ควบคุมข้อมูล | ข้อมูลลูกค้าของตน | ระบบต้องช่วยร้านทำหน้าที่: privacy notice generator, consent (แยกวัตถุประสงค์: ธุรกรรม/การตลาด), export/ลบรายบุคคล, บันทึก consent พร้อมเวลา/IP |

- **ข้อมูลอ่อนไหว** (สุขภาพในคลินิก, ศาสนา, ชีวมิติ): ต้องมี explicit consent, เข้ารหัส, จำกัดสิทธิ์, access log, เก็บแยก
- **แจ้งเหตุรั่วไหล** ต่อ สคส. ภายใน 72 ชม. (และร้านต้องแจ้งเจ้าของข้อมูลเมื่อเสี่ยงสูง) → ต้องมี runbook
- **การส่งข้อมูลไปต่างประเทศ** (เซิร์ฟเวอร์สิงคโปร์, บริการสหรัฐฯ เช่น Vercel/Resend): ต้องระบุใน privacy notice และมีมาตรการตามมาตรา 28–29; ลูกค้าที่อ่อนไหวสูงเสนอ region กรุงเทพฯ (เฟสหลัง)
- Cookie banner, นโยบายการเก็บรักษา (เช่น log 90 วัน, ข้อมูลร้านที่ยกเลิก 30 วัน)

### 8.2 ธุรกิจและภาษี

- **ทะเบียนพาณิชย์อิเล็กทรอนิกส์ (DBD)** สำหรับแพลตฟอร์ม และแนะนำ/บังคับร้านในหมวดเสี่ยง (เติมเกม) พร้อมแสดงเครื่องหมาย
- **VAT 7%** เมื่อรายได้เกิน 1.8 ล้านบาท/ปี (หรือจดสมัครใจเพื่อออกใบกำกับภาษีให้ลูกค้านิติบุคคล); ระบบบิลต้องออกใบกำกับภาษี/ใบเสร็จ, รองรับ e-Tax Invoice by Email
- ลูกค้านิติบุคคลจ่ายค่าบริการอาจ **หัก ณ ที่จ่าย 3%** → ระบบรองรับยอดสุทธิและอัปโหลดหนังสือรับรอง
- ค่าบริการต่างประเทศ (Vercel, Supabase ฯลฯ) อาจถูกเรียกเก็บ VAT 7% (e-Service) หรือต้องนำส่ง ภ.พ.36 — ปรึกษาบัญชี
- สัญญาบริการ (ToS): ขอบเขต, SLA, ข้อจำกัดความรับผิด, การระงับ, การคืนเงิน, ทรัพย์สินทางปัญญา (ธีมเป็นของแพลตฟอร์ม, เนื้อหาเป็นของร้าน), DPA, กฎหมายที่ใช้บังคับ

### 8.3 ข้อกำหนดเฉพาะประเภทเว็บ

| ประเภท | สิ่งที่ต้องระวัง | สิ่งที่ระบบควรทำ |
|---|---|---|
| คลินิก | พ.ร.บ.สถานพยาบาล: โฆษณาต้องขออนุญาต (ก่อน-หลัง, ราคาลด, อ้างสรรพคุณ); ข้อมูลสุขภาพ | คำเตือนในหลังบ้านตอนใส่รูปก่อน-หลัง/โปรโมชัน, ฟิลด์เลขใบอนุญาตสถานพยาบาล, เข้ารหัสเวชระเบียน |
| เติมเกม/ดิจิทัล | ขอบเขต e-money (ธปท.): wallet ใช้ได้เฉพาะในร้าน ห้ามถอน; ห้ามเกมพนัน; ฉ้อโกง/ฟอกเงิน | wallet ต่อ tenant, ไม่มีถอนเงินสด, จำกัดวงเงิน/วัน, KYC-lite ร้าน, บล็อกคีย์เวิร์ดพนัน |
| ร้านอาหาร/อาหารเสริม/เครื่องสำอาง | โฆษณาอาหาร/ยา/เครื่องสำอาง (อย.) | ฟิลด์เลข อย., คำเตือนการอ้างสรรพคุณ |
| เหล้า/บุหรี่/บุหรี่ไฟฟ้า/อาวุธ/ยา | ห้ามขายออนไลน์ | นโยบายเนื้อหา + keyword block + takedown |
| อสังหาฯ/รถ | ข้อมูลเจ้าของทรัพย์, พ.ร.บ.ขายตรงฯ | ฟอร์มสอบถามมี consent |
| การขายทั่วไป | พ.ร.บ.ขายตรงและตลาดแบบตรง, คุ้มครองผู้บริโภค (แสดงราคา ชื่อผู้ขาย นโยบายคืน) | หน้าข้อมูลผู้ขายบังคับ, นโยบายคืนสินค้า generator |
| ทุกประเภท | ลิขสิทธิ์รูป/ฟอนต์/ธีม | ใช้ Google Fonts + รูปตัวอย่างที่มีสิทธิ์ (Unsplash/ถ่ายเอง), แจ้งร้านเรื่องรูปที่อัปโหลด |
