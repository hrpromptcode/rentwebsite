## 1. เป้าหมายธุรกิจ

- สร้าง **แพลตฟอร์มเดียว** ที่ให้เช่าเว็บไซต์สำเร็จรูปแก่ธุรกิจทุกประเภทในไทย: เว็บเติมเกม, ร้านค้าออนไลน์, จองคิว, คลินิก, ร้านอาหาร, โรงแรม, คอร์สเรียน, บริษัท/พอร์ตโฟลิโอ ฯลฯ
- รายได้หลัก = **ค่าเช่ารายเดือน/รายปี** ต่อ tenant + ค่าบริการเสริม (โดเมน, ตั้งค่าเริ่มต้น, ธีมพรีเมียม)
- ลูกค้าต้อง **เปิดเว็บได้เองภายในไม่กี่นาที** จากเทมเพลต และ **ดูแลเองได้โดยไม่ต้องพึ่งคุณ**
- คุณ (เจ้าของแพลตฟอร์ม) ต้องดูแลลูกค้าหลายร้อยรายได้ด้วยทีมเล็ก → ทุกอย่างต้องอัตโนมัติ: สมัคร, สร้างเว็บ, เก็บเงิน, ต่อโดเมน, ระงับเมื่อค้างชำระ

## 2. หลักคิดที่สำคัญที่สุด: "อย่าสร้างเว็บ 10 แบบ ให้สร้างแพลตฟอร์มเดียวที่ประกอบร่างได้"

ความผิดพลาดที่พบบ่อยคือการทำเว็บเติมเกม 1 ชุด เว็บร้านอาหาร 1 ชุด เว็บคลินิก 1 ชุด แยกโค้ดกัน ซึ่งจะดูแลไม่ไหวตั้งแต่ประเภทที่ 4

แนวทางที่ถูกต้อง:

```
ประเภทเว็บไซต์ (Site Type / Template)
  = ชุดโมดูลที่เปิดใช้ (Modules)
  + ธีมตั้งต้น (Theme preset: สี ฟอนต์ เลย์เอาต์)
  + หน้าเว็บตั้งต้น (Pages ที่ประกอบจาก Sections)
  + ข้อมูลตัวอย่าง (Seed data)
  + เช็กลิสต์เริ่มต้นใช้งาน (Onboarding checklist)
```

ตัวอย่าง:

| ประเภทเว็บ | โมดูลที่เปิด |
|---|---|
| ร้านค้าออนไลน์ | CMS + Commerce + Payments + Shipping + Promotions |
| เว็บเติมเกม | CMS + Top-up + Wallet + Payments (+ Commerce แบบสินค้าดิจิทัล) |
| คลินิก | CMS + Booking + Patient Records + Commerce (คอร์ส/แพ็กเกจ) + Payments |
| ร้านอาหาร | CMS + Menu + QR Ordering + Reservation + Payments |
| จองคิวร้านเสริมสวย | CMS + Booking + Staff + Payments (มัดจำ) |
| เว็บบริษัท | CMS + Forms + Blog |

โมดูลแต่ละตัวเขียน **ครั้งเดียว** ใช้ซ้ำได้ทุกประเภท การ "เพิ่มประเภทเว็บใหม่" ส่วนใหญ่จึงเป็นแค่การสร้างเทมเพลตใหม่จากโมดูลที่มีอยู่ ไม่ใช่การเขียนโค้ดใหม่

## 3. สรุปการตัดสินใจหลัก

| # | เรื่อง | ตัดสินใจ | เหตุผลสั้น ๆ |
|---|---|---|---|
| 1 | รูปแบบโค้ด | 1 monorepo, 1 แพลตฟอร์ม, ระบบโมดูล + เทมเพลต | ดูแลได้ด้วยทีมเล็ก, เพิ่มประเภทเว็บได้เร็ว |
| 2 | การแยกข้อมูลลูกค้า | **Pooled**: Postgres ก้อนเดียว, ทุกตารางมี `tenant_id`, บังคับด้วย Row Level Security (RLS) | ถูกที่สุด, migrate ง่าย, รองรับหลายพันร้าน; แพ็กเกจองค์กรค่อยแยก DB ภายหลัง |
| 3 | URL ของลูกค้า | `{slug}.rentweb.app` ฟรี + โดเมนส่วนตัวผ่าน CNAME (SSL อัตโนมัติ) | มาตรฐานเดียวกับ Shopify/Wix |
| 4 | หน้าบ้าน | **Next.js (App Router) + TypeScript + Tailwind CSS + shadcn/ui** | SEO ดี (SSR/ISR), multi-tenant middleware, ecosystem ใหญ่สุด |
| 5 | หลังบ้าน | Next.js Server Actions/Route Handlers เป็น BFF + **Worker แยก** สำหรับงานเบื้องหลัง (คิว, cron, webhook) | ภาษาเดียว (TypeScript) ทั้งระบบ, ทีมเล็กทำได้ |
| 6 | ฐานข้อมูล | **PostgreSQL (Supabase)** + Drizzle ORM | ได้ Auth, Storage, RLS, Backup ในที่เดียว; ย้ายออกได้เพราะเป็น Postgres มาตรฐาน |
| 7 | Cache / คิว | Redis (Upstash) | เก็บ hostname→tenant, rate limit, คิวงาน |
| 8 | ไฟล์/รูป | Cloudflare R2 (+ Cloudflare CDN) | ไม่คิดค่า egress → ประหยัดมากเมื่อร้านค้ามีรูปเยอะ |
| 9 | Hosting ช่วงแรก | Vercel (แอป) + Supabase + Cloudflare | เริ่มเร็วที่สุด; ออกแบบให้ย้ายไป VPS/Docker ได้เมื่อค่าใช้จ่ายสูง |
| 10 | การรับเงินของร้านค้า | **ร้านค้าเชื่อมบัญชี payment gateway ของตัวเอง** (Opn, GB Prime Pay, Stripe) + โอนเงิน/แนบสลิป + ตรวจสลิปอัตโนมัติ | เงินไม่ผ่านมือคุณ → ไม่ต้องขอใบอนุญาต e-payment, ลดความเสี่ยง |
| 11 | การเก็บค่าเช่า | Stripe Billing หรือ Opn Recurring + PromptPay | อัตโนมัติ, ระงับเว็บเมื่อค้างชำระ |
| 12 | ปรับแต่งได้แค่ไหน | ธีมผ่าน design tokens (สี ฟอนต์ มุมโค้ง เลย์เอาต์) + page builder แบบ sections; **ไม่ให้ใส่โค้ดเอง** (Custom CSS เฉพาะแพ็กเกจสูง) | ป้องกันเว็บพัง/ช่องโหว่, ดูแลง่าย |
| 13 | ลำดับการสร้าง | Core → Commerce → Booking → Top-up → Restaurant → ที่เหลือ | Commerce ใช้ซ้ำมากที่สุด, Booking ครอบคลุมคลินิก/สปา/ฟิตเนส |
| 14 | ภาษา | ไทยเป็นหลัก, โครงสร้างรองรับ i18n (EN) ตั้งแต่แรก | ตลาดไทยก่อน, แต่ไม่ต้องรื้อภายหลัง |

## 5. สมมติฐานที่ใช้ทั้งเอกสาร

- ทีมพัฒนา **1–2 คน** ในช่วงแรก (ถ้ามากกว่านี้ เวลาสั้นลงตามตารางใน 04)
- ตลาดหลักคือ **SME ไทย** ที่ไม่มีทีมเทคนิค ต้องการเปิดเว็บเองง่าย ๆ ราคาไม่กี่ร้อยถึงไม่กี่พันบาท/เดือน
- อัตราแลกเปลี่ยนที่ใช้คำนวณ **฿34 / USD** (ปรับตามจริง) และราคาบริการเป็นราคา ณ ต.ค. 2026 ที่ค้นได้ (ดูแหล่งอ้างอิงท้าย 05)
- เริ่มจาก region สิงคโปร์ (ใกล้ไทย, ราคาถูก, บริการครบ) และพิจารณา AWS/Google Cloud กรุงเทพฯ เมื่อมีลูกค้าที่ต้องการเก็บข้อมูลในประเทศ

## 6. Roadmap ย่อ (รายละเอียดใน 04)

| เฟส | ระยะเวลา (1–2 คน) | ส่งมอบ |
|---|---|---|
| 0 Foundation | 3–4 สัปดาห์ | monorepo, tenant resolution, auth, DB+RLS, theme engine, admin shell, billing |
| 1 Commerce + CMS | 5–6 สัปดาห์ | ร้านค้าออนไลน์, page builder, รับเงิน (PromptPay/สลิป), 3 เทมเพลตแรก → **เปิด beta** |
| 2 Booking | 4–5 สัปดาห์ | จองคิว, คลินิก, สปา/ซาลอน, ฟิตเนส, แจ้งเตือน LINE |
| 3 Top-up + Restaurant | 5–6 สัปดาห์ | เว็บเติมเกม (wallet, supplier), ร้านอาหาร (เมนู, QR สั่งที่โต๊ะ, จองโต๊ะ) |
| 4 ขยาย | ต่อเนื่อง | โดเมนอัตโนมัติเต็มรูปแบบ, โรงแรม/เช่า, คอร์สเรียน, อีเวนต์, API/webhooks, ตลาดธีม |

รวมถึงจบเฟส 3 (ครบ 5 ประเภทหลัก) ≈ 34–42 person-week: **ทีม 2 คน ≈ 4.5–5.5 เดือน**, ทำคนเดียว ≈ 9–11 เดือน (รายละเอียดและทางเลือกการจ้างใน 04 ข้อ 4)

## 7. คำถามที่คุณต้องตอบก่อนลงมือ (มีผลต่อแผน)

1. **จดบริษัทแล้วหรือยัง?** มีผลต่อ (ก) จดโดเมน `.co.th` (ต้องใช้เอกสารบริษัท/เครื่องหมายการค้า) (ข) สมัคร payment gateway บางเจ้า (ค) การออกใบกำกับภาษีให้ลูกค้า
2. **จะให้เงินของร้านค้าผ่านบัญชีคุณไหม?** แผนนี้เลือก "ไม่ผ่าน" (ร้านใช้บัญชี gateway ตัวเอง) ถ้าอยากเก็บค่าธรรมเนียมต่อรายการแบบ marketplace ต้องศึกษาใบอนุญาตจากธนาคารแห่งประเทศไทย (ธปท.) ก่อน
3. **เว็บเติมเกมจะดึงสินค้าจากที่ไหน?** ต้องมี supplier (API ขายส่งบัตร/โค้ดเติมเกม) หรือให้ร้านอัปโหลดสต็อกโค้ดเอง — มีผลต่อการออกแบบโมดูล Top-up
4. **ระดับการปรับแต่ง**: ยอมรับได้ไหมว่าลูกค้าปรับได้แค่ภายในกรอบธีม (สี ฟอนต์ เลย์เอาต์ sections) และไม่สามารถใส่โค้ดเองได้? (แนะนำ: ใช่ อย่างน้อยปีแรก)
5. **งบและทีม**: ทำเอง / จ้างเพิ่ม / จ้างเอเจนซี่ — ดูสถานการณ์ค่าใช้จ่ายใน 05
6. **ชื่อแบรนด์และโดเมนหลัก** (ต้องจองก่อนเพราะ subdomain ของลูกค้าทุกคนจะผูกกับชื่อนี้ เปลี่ยนภายหลังยาก)
